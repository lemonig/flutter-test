## 二、规划原则

- **按模块组织**，每个模块独立可验收，模块内任务按依赖顺序排列。
- 优先级：**P0** MVP 必须、**P1** 功能完整、**P2** 体验与发布。
- 复杂度用 S / M / L 表示（S≈单点改造、M≈新增页面或接口链路、L≈多页联动或原生能力接入），不作为工期承诺。
- 每个模块的验收标准以「可操作 + 可观察结果」描述，便于写成测试用例。
- 现有目录遵循 `features/<module>/{data,providers,presentation}`，新模块沿用同一分层，不引入第二套架构。
